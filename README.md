# dsh-session-eraser

**删除应该是真的删除，但误删不该变成事故。**

Delete should mean delete — and a misclick shouldn't mean disaster.

DeepSeek Harness 插件 · Web GUI · 需要 DSH ≥ 0.2.2-rc.5 · MIT

**简体中文** · [English](./README.en.md)

DeepSeek Harness（DSH）的会话只有 fork 和归档，没有删除：会话越攒越多，想彻底移除一个却无从下手。这个插件给会话右键菜单补上缺失的「删除会话」：会话目录从磁盘移走，工作区、置顶、归档引用一并清掉，侧栏立即刷新——但目录不是被直接抹除，而是移进回收目录。再加上一个能看、能还原、会自动过期的回收站，删错了也有退路。

> 在侧栏右键一个会话 → 选择红色的「**删除会话**」→ 在弹出的确认框里点「**是，删除**」
>
> 会话立即从列表消失，并弹出「会话已删除」提示。想看删掉的会话：同一菜单里的「**回收站**」。

**它删得干净，但留了一条后悔药：回收站。**

> **当前版本：v0.2.1** — 由主机端（`index.js`，注册删除与回收站路由）与客户端（`client.js`，注册右键菜单动作与回收站面板）两半组成。删除前会弹出确认框（显示会话标题与「否」「是，删除」两个按钮）；仍在运行的会话会被拒绝删除。仅支持 Web GUI。

## 功能与当前状态

| 环节 | 做什么 | 当前状态 |
| --- | --- | --- |
| **菜单入口** | 在会话右键菜单里加一条红色、带分隔线的「删除会话」，排在归档之后 | 会话服务报告该会话正在运行时该项置灰并改显示「该会话正在运行，无法删除」；无论如何主机端都会先以 `409` 拒绝 |
| **确认弹窗** | 点「删除会话」先弹出确认框，显示会话标题、「否」与红色「是，删除」；点遮罩或按 Esc 等同「否」 | 渲染在全局浮层（`shell.overlay`）里，单次误触不会删掉任何东西 |
| **移入回收目录** | 把会话目录移入 `$DSH_HOME/session-delete-trash/`，而不是直接 unlink | 目录名保留时间戳、工作区与原目录名，方便对应恢复 |
| **回收站面板** | 同一菜单里的「回收站」打开列表面板：会话目录、来源工作区、删除时间、体积 | 可单条还原到原工作区、单条彻底删除，或二次点击清空整个回收站 |
| **保留期过期** | 超过保留期（默认 30 天，`DSH_SESSION_DELETE_RETENTION_DAYS` 可调）的条目永久清除 | 在列举回收站或执行删除时顺带清理，不占后台常驻 |
| **批量删除** | `POST /session-delete/delete` 除单个 `sessionId` 外也接受 `sessionIds`（最多 50 个） | 逐条返回结果：全部成功 `200`、全部被占 `409`、部分成功 `207` |
| **清理引用** | 一次清掉投影缓存、工作区的 `sessionIds` 成员、置顶与归档引用（走持久化工作区注册表） | 各项清理互相独立，单项失败不回滚已完成的删除，只记日志 |
| **即时刷新** | 广播官方 `api-session/removed` 事件 | 侧栏与工作区视图立即更新，无需刷新页面 |
| **运行中保护** | 正在运行的会话日志文件被占用，删除返回 `409` 并提示先停止 | 移动失败时已移动的目录会尽力回滚，保证不删一半 |
| **同源校验** | 所有路由校验 `Origin`/`Host` 与 `Sec-Fetch-Site`，并拒绝无 Origin 的非 JSON 写请求 | 别的站点页面无法通过跨站请求删掉你的会话 |
| **还原不覆盖** | 还原时若目标位置已有同名会话目录，返回 `409` 而不是覆盖 | 宁可失败也不让两份日志互相污染 |
| **删除当前会话** | 删掉主视图里正打开的会话后，页面自动重载 | 回到一个新的空白会话，不会停在失效视图上 |

### 删除时发生了什么

1. 客户端把 `sessionId`（或 `sessionIds` 数组）发给主机端路由 `POST /session-delete/delete`；主机先做同源校验，再校验 id 格式。
2. 主机在所有工作区下查找该会话的磁盘目录——原始 id、`session-` 前缀有无、路径编码形式都会尝试，避免因 id 写法不同而找不到。
3. 找到的目录逐个移入回收目录；任一移动失败则回滚已移动的目录并返回 `409`，不留副作用。
4. 随后清投影缓存，并通过工作区注册表解除置顶、取消归档、从各工作区摘除该会话。
5. 最后广播 `api-session/removed`，所有客户端立即把该会话从列表移除。

### 回收站里有什么

| 路由 | 方法 | 作用 |
| --- | --- | --- |
| `/session-delete/trash` | GET | 列出条目（目录、工作区、删除时间、体积）、保留天数、本次过期清理数 |
| `/session-delete/trash/restore` | POST | 把条目移回 `sessions/<工作区 key>/<原目录名>`，目标已存在则 `409` |
| `/session-delete/trash/purge` | POST | 永久删除单条 |
| `/session-delete/trash/empty` | POST | 清空回收站（要求 `{ "confirm": true }`） |

条目名形如 `<时间戳>--<工作区 key>--<原目录名>`；工作区 key 本身含 `--`，所以解析时中间段按贪婪匹配，并以尾部目录名收口。所有条目名在使用前都会校验必须是回收站根目录的直接子项。

## 安装

```sh
dsh plugin --profile <name> add dsh-session-eraser
```

也可以安装本地目录或 git URL。装好后刷新 Web GUI（Ctrl+R），让客户端 bundle 加载生效。

## 用法

1. 在侧栏右键一个会话（或打开它的「…」菜单）。
2. 选择「**删除会话**」，弹出确认框，点「**是，删除**」才真正删除（「否」/遮罩/Esc 都会取消）。
3. 会话从列表消失，右下角弹出确认提示。
4. 要恢复：同一菜单里选择「**回收站**」，在列表里点「还原」，会话回到原工作区。

### 不经过界面的恢复方式

回收站目录里的名字形如 `<时间戳>--<工作区 key>--<原目录名>`，把整个目录移回原位置也能恢复：

```sh
mv "$DSH_HOME/session-delete-trash/<时间戳>--<工作区 key>--<原目录名>" \
   "$DSH_HOME/sessions/<工作区 key>/<原目录名>"
```

移回后刷新 GUI，会话会重新出现在列表里。

## 边界与限制

- **确认框是自己实现的。** DSH 没有给插件开放确认对话框，也不允许插件引用内置 UI 组件库，所以确认框是插件自己的组件，注册在框架级浮层 `shell.overlay` 里（与官方的重命名弹窗同一层），样式只用了主题变量，跟随明暗主题。
- **误删也可救回。** 即便确认后删掉了，会话目录仍完整躺在回收站里，可在「回收站」面板还原，
- **运行中的会话删不掉。** 日志文件被占用时删除会被拒绝（`409`），先让它停下来再删；在 Windows 上这一点尤其明显。
- **子代理子会话不级联。** 会话日志是压缩的追加式文件，它和投影缓存都没有父→子会话指针，所以子会话需要在各自的列表里单独删除。
- **只清自己管辖的范围。** 清理的是磁盘日志、工作区成员关系、置顶/归档引用与投影缓存；第三方插件自己维护的索引（如上下文洞察、记忆系统）可能仍保留该会话的引用，需要在那些插件里各自清理。
- **不碰工作区里产出的文件。** 只有会话日志目录进回收站，会话写过的文件留在原地。
- **仅 Web GUI。** 客户端依赖 Web 端的上下文菜单、插槽与布局服务，没有覆盖其他端。

## 接下来做什么

以下为设想，尚未排期，欢迎在 issue 里讨论优先级：

| 方向 | 说明 |
| --- | --- |
| **子代理树级联** | 等日志或投影里出现可用的父子指针后，删父会话时连带清理其子代理会话 |
| **产出文件清单** | 删除前列出该会话在工作区里写过的文件，由用户决定是否一并清理 |
| **5 秒撤销** | 删除后给一个短暂的可撤销窗口，撤销即从回收站移回 |
| **搜索与预览** | 回收站面板里支持按标题搜索、查看会话正文片段再决定还原还是彻底删 |
| **agent 工具** | 暴露一个让 agent 自己列出/清理回收站的工具 |
